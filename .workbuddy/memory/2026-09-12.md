- 技术栈：**Spring Boot 3.5.16 + Java 17**（本机无 JDK21，按"优先兼容"原则选 17；Boot 3.5.16 本地仓库已缓存）+ Maven（无全局 mvn，用 `~/.m2/wrapper/dists/apache-maven-3.9.16/56ba1f9f/bin/mvn`）+ springdoc 2.8.9（Swagger）。未引入 Spring AI（Phase 2 再评估），先建自有 LLMService/EmbeddingService 接口 + Ollama 实现。
- 结构：backend/src/main/java/com/obsidianmind/{controller,service,repository,domain,dto,parser,config,exception,util}。VaultRepository=文件系统唯一边界；Note id=Vault 相对路径；扫描只收集元数据不读正文；保存=临时文件+ATOMIC_MOVE 原子写回。
- 关键设计：搜索 score 诚实标注 TEXT_MATCH（非向量）；Index 状态机 IDLE/SCANNING/INDEXING/READY/FAILED（@Async，仅解析→Chunk 不连 Milvus）；Chat Mock + SSE（phase/message/done 事件）；Ollama/Milvus 健康检查按需探测不阻塞启动；VaultPaths 防路径穿越；统一异常信封 {code,message,timestamp}。
- **PathPattern 坑**：Boot 3 默认 PathPatternParser 要求 `{*id}` 必须在路径末尾，`/{id}/backlinks` 无法表达 → backlinks 改用 `GET /notes/backlinks?note={id}`（字面量路由优先于 `{*id}` 捕获不冲突）。
- **并行 Edit 同一文件会互相覆盖**（本轮 BusinessException import 被覆盖导致编译错误反复）；同一文件多处修改必须串行 Edit。
- **沙箱网络坑**：WorkBuddy 沙箱注入 `SERVER__PORT=51715`（Spring relaxed binding 生效→应用随机端口）；本地回环被透明代理拦截（curl 直连/显式代理均 AUTH_REQUIRED，agent-browser 也无法访问本地端口）→ **沙箱内无法对本地端口做实机 HTTP 冒烟**，验收以 MockMvc 集成测试为准（37/37 全绿），实机 curl 由用户本地终端执行。
- 交付：mvn test 37/37；package 产出 obsidianmind-backend-0.1.0.jar；docker-compose.milvus.yml（Milvus standalone+etcd+minio）；前端 vite.config.ts 加 /api→8080 代理（注意沙箱内 SERVER__PORT 会覆盖 8080，用户本机正常）。

- **关键 bug（实测抓出并修复）**：
  1. `refresh()` 增量 diff 恒为空——scan() 内部更新了 lastScanPaths，自己和自己 diff → 移出 scan()，新增 baseline()，scanAndLoad 后调用。

  3. FileTree 只调 openNote 不走路由 → NoteView 的 route watcher 不触发（轮询/Backlinks 全不启动）→ 拆成 route watcher 负责加载 + currentNote.id watcher 负责副作用。

  5. OPFS 根 handle.name 为空字符串 → displayName/buildTree 兜底「演示 Vault」。
  6. resolveLinks 用 readRaw 不进缓存 → backlinksOf 永远空 → resolveLinks 改为填充 contentCache。
